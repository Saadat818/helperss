1 ЭТАП - Разработать сценарии для ТОП тематик обращений в виде блок-схем в Helper 
(Вкладка в хелпер)

Заказчик: Давид Кан

Цель: Разработать отдельную вкладку для сотрудников КЦ. Вкладка предоставляет сотрудникам пошаговые сценарии консультаций в формате интерактивного дерева решений и позволяет глав.спецам  самостоятельно управлять контентом. 
Ожидаемый эффект от внедрения:
Навигация по тематикам в формате «шаг за шагом».
Минимизация ошибок и «человеческого фактора».
Сокращение времени на обучение новичков.
Работа всегда по актуальным версиям сценариев.
   1. 1. Получаем на 1 этапе разработки: 
Отдельную вкладку «Сценарии» в системе Helper;
Функционал для сотрудников КЦ: поиск, просмотр, прохождение сценария;
Функционал для редакторов: создание/редактирование визуальные схемы  сценарии через встроенный редактор:
создание нового сценария;
редактирование существующего;
удаление / архивирование;
публикация черновика;
копирование сценария
Поддерживать импорт из шаблонов 
Поддерживать экспорт сценария
в Excel;
в JSON;
в PDF;
в изображение / SVG / PNG блок-схемы.
Встроенный редактор блок-схем (drag & drop);
Версионирование и управление доступом (RBAC).
Генерация мануала
Система должна логировать каждое открытие сценария и формировать рейтинг популярности за последние 30 дней 

* На будущее оставить возможность интеграции с внешними CRM / тикет-системами (авторский миро Элтурана) 


Глоссарий
Термин
Определение 
Helper
Внутренняя система КЦ, в которую встраивается разрабатываемый модуль 
Сценарий


Интерактивное дерево решений, описывающее пошаговый алгоритм консультации клиента по конкретной тематике обращения 
Узел (Node)
Элемент дерева решений: вопрос, условие или финальный ответ. Узлы соединяются направленными ребрами (стрелками) 
Корневой узел
Начальный узел сценария — отправная точка для оператора 
Финальный узел
Конечный узел, содержащий готовый ответ клиенту, инструкцию оператору и сопутствующие материалы 
Хлебные крошки (Breadcrumb)
Визуальная цепочка пройденных узлов, отображаемая при прохождении сценария 
Черновик
Несохраненная или неопубликованная версия сценария, видимая только редакторам 
Публикация
Перевод сценария из статуса «Черновик» в «Активный» — становится доступным операторам 
Архивирование
Скрытие сценария от операторов без удаления данных 
Версия
Снапшот опубликованного сценария с порядковым номером (v1, v2...) 
RBAC
Role-Based Access Control — управление доступом на основе ролей 
Оператор
Сотрудник КЦ, использующий сценарии для консультаций. Только чтение 
Редактор
Сотрудник, имеющий право создавать и редактировать сценарии 
Главный специалист / Админ
Пользователь с полными правами: публикация, удаление, управление ролями 
draw.io / diagrams.net
Внешний редактор блок-схем, чьи форматы (.xml) поддерживаются при импорте 
Топ обращений
Список сценариев, ранжированных по частоте использования операторами 
Toast-уведомление
Всплывающее краткосрочное сообщение о результате действия 
Мануал
Автоматически генерируемый документ-инструкция на основе содержимого сценария

Функциональные требования 
  4.1.  Для сотрудников КЦ: 
Поиск по названию сценария и ключевым словам
Категории тематик (группировка)
Список «Топ обращений» с бейджем частоты
Фильтр по категории, статусу, дате обновления
Сортировка списка: по названию (А-Я), дате обновления, частоте использования 
Раздел «Недавно просмотренные» — до 5 последних сценариев, открытых текущим пользователем 

4.2. Прохождения сценария: 
Сценарий открывается с корневого стартового узла
Оператор нажимает один из вариантов ответа → переход к следующему узлу
Отображается хлебная крошка (breadcrumb) — цепочка пройденных шагов
Кнопка «← Назад» — возврат к предыдущему узлу
Кнопка «Начать заново» — сброс к стартовому узлу
Прогресс-индикатор (глубина / примерное число шагов до финала)
Возможность открыть полную схему в режиме read-only (обзорный вид) и сгенерировать мануал. 
4.3.  Финальный узел — ответ оператору
На финальном узле оператор видит:
Готовый текст ответа клиенту (с кнопкой «Копировать»)
Внутреннюю инструкцию для сотрудника
Перечень необходимых документов
Ограничения и условия
Связанные ссылки (при нажатие переход в мвики для полноты информации) 
Примечания / служебные комментарии

4.4. Админский доступ
         4.5. Управление сценариями
                      Создание нового сценария с заданием названия, категории, тегов
                        Редактирование существующего
Копирование сценария
Публикация черновика / перевод в архив
Удаление (с подтверждением)
*Сценарии создается на стороне заказчиков
4.6. Встроенный редактор блок-схем
          4.7.   Возможности редактора:
Создание сценария: ввод названия (обязательно), выбор категории (обязательно), ввод тегов (опционально), описания 
Редактирование существующего сценария 
Копирование сценария — создание полного дубликата со статусом «Черновик» 
Публикация черновика — перевод в статус «Активный» с созданием новой пронумерованной версии 
Архивирование — скрытие сценария от операторов без удаления 
Удаление — безвозвратное удаление черновика с двойным подтверждением
